# Journal 08: Baton Link, the zero-install path

Prompt 007 asked for something easier. The answer: **a bookmark that captures, and a link that any AI can read.**

## Why a bookmark and not a server fetch

The first attempt let the relay fetch a ChatGPT share link itself (`relay/https://chatgpt.com/share/…`).
**Real result: chatgpt.com answers the Cloudflare Worker with HTTP 403.** Servers are blocked; the user's own browser is not.
So the capture moves into the page, as a bookmarklet that runs with the user's session (bookmarklets are exempt from the
page's script CSP in Chrome and Firefox).

## Transport, chosen from the real headers

Measured in Chromium on 2026-10-11:

| Site | COOP | CSP `form-action` | Popup + postMessage | Form POST |
|---|---|---|---|---|
| chatgpt.com (share page) | same-origin-allow-popups | none | works | works |
| claude.ai | same-origin | `http: https:` | **breaks** (opener severed) | works |
| gemini.google.com | same-origin-allow-popups | Google hosts only | works | **blocked** |

No single transport covers all three, so the bookmarklet:

1. opens `about:blank` **synchronously** (keeps the click's user activation, and a same-origin blank tab survives COOP),
2. submits a hidden form POST into that tab → relay `/api/ingest-form` → 303 to the Baton Link,
3. on Gemini (or any `form-action` violation) navigates the tab to `/receive` and hands the data over with `postMessage`.

What each site gives the bookmarklet:

- **ChatGPT `/c/…`:** the full conversation JSON from `/backend-api/conversation/<id>` (tool outputs, code, files metadata), via
  the page's own session. **Share pages:** the full HTML, parsed by the same decoder as the CLI.
- **Claude `/chat/…`:** `chat_conversations/<id>?render_all_tools=true` (artifacts, tool calls) via the page's own session.
- **Gemini and anything else:** visible turns from the live DOM, read from **clones** so the page is never modified.

## The Baton Link

`/h/<code>` now serves one page for two audiences:

- **people:** title, counts, what was lost, and *Continue in Claude* (`claude.ai/new?q=`), *Continue in ChatGPT* (`chatgpt.com/?q=`),
  *Continue in Gemini* (copies the prompt, opens Gemini), copy link, zip, full transcript;
- **AIs:** the full brief as plain text in the page (`<pre>`), plus `.md` (plain text) and `.zip` variants.

## Real tests (no mocks)

All against the live relay `https://baton-relay.nimitjain-248.workers.dev`, using the bookmarklet code exactly as the live home page serves it,
executed in a real Chromium on the real sites:

| Test | Result |
|---|---|
| Real ChatGPT share page (cricket chat) → bookmarklet → form POST → relay | ✅ `BTN-0NSQ-64G6-3VKJ`: 8 prompts, 133 tool calls, 16 files recovered, 16 lost listed |
| Real Gemini, a signed-out chat typed in the browser → bookmarklet → popup path → relay | ✅ `BTN-0Z5G-0MB9-DP0Z`: prompt and answer captured |
| A real AI fetcher (Claude Code WebFetch) opens each link | ✅ restated the goal, where it stopped, the latest instruction and the file list |

Bugs the real runs found, now fixed:

- The receive popup hung on `await navigator.clipboard.writeText` (no focus → the promise never settles). It is now capped at 800 ms.
- Gemini's DOM carries a hidden screen-reader copy of each prompt ("You said …"). Visually-hidden nodes are now stripped
  (bookmarklet and extension adapter).

**Not verified here, needs the owner's logins:** the bookmarklet on a signed-in `chatgpt.com/c/…` chat and on `claude.ai/chat/…`
(both call the site's own API with the user's session), and a click from a real bookmarks bar rather than injected by the test driver.
Playwright's `evaluate` also bypasses page CSP, as a bookmark does, so that part matches. COOP, form-action and popup behaviour were real.

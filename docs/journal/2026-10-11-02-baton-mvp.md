# Journal 02: First working Baton surfaces

**Window:** 2026-10-11, after the research and product decision in Journal 01.

## Scope decision

The linked share is titled *Cricket Stumping Simulation*, but the follow-up prompt in `docs/prompts/003-the-exact-problem.md` reframes it: the product is the friction of moving AI work, and the cricket conversation is the first test fixture. Work in this stage follows that product definition. The separate simulation prototype created during initial interpretation is kept outside the Baton repository.

## Built in this stage

- A shared, dependency-free normalizer for ChatGPT public-share HTML and exports, Claude exports, Claude Code JSONL, Markdown, and text.
- A Node CLI that imports a file or public URL and writes a directory or ZIP handoff.
- A static browser page that parses local files and downloads a ZIP without an upload service.
- A stdio MCP server with a `baton_import` tool, plus the receiving-agent Skill.
- Draft payload builders for Salesforce, Jira, Zendesk, and Slack.
- A v1 bundle-format note and a manifest with SHA-256 hashes.

## Known gaps

- The ChatGPT share stream is undocumented and can change; the source is retained for reprocessing.
- In-browser ZIP input is not supported yet. Import the underlying HTML/JSON file instead.
- Connector payload builders do not authenticate or deliver records.
- The MCP server supports import; `baton_recover` and `baton_sink` are future tools.
- Recovery is limited to visible shell heredocs and never executes code.
